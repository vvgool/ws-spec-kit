# 审查文档质量

对照事实清单审 diff。准确且完整才能批准。

## 步骤

1. **钉变更**
   读允许路径内的 diff 与事实清单。完成：每处改动都已看见。

2. **审准确**
   句子不得与代码、配置或原文冲突。完成：过时或臆造句都是 finding。

3. **审完整**
   事实清单里要公开的点都有落点。完成：缺口都列出来。

4. **交审查结果**
   完成：`approved` 仅在准确且完整时为真。

## 规则

- 不改文档。修复走 documentation-editing。
- 事实对不上：停止并报告阻塞。
