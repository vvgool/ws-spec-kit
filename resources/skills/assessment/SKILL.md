# 只读评估

读取 requirement-source，明确评估对象、问题和版本范围。用户没有要求实施时，评估不转入开发交付。

1. 从代码、配置、已有验证结果及授权的只读查询中收集事实。记录文件路径、版本或来源；区分当前证据、历史结论与推断。
2. 按影响排列发现，每项说明触发条件、证据、影响及建议。没有发现缺陷不等于通过真实验收。
3. 输出 assessment-report：评估范围与版本、主要结论、证据、问题及优先级、未验证事项和下一步。结论可以是通过、不通过或证据不足；不得用 Workflow 完成替代上线批准。

## 边界

- 不修改项目文件，不创建 Git Worktree，不提交、发布或更新外部 Issue/Wiki。
- 只通过 Work Package 授权的 draft/Artifact 目录记录评估，不写入业务文档路径。
- 不运行会写入构建产物、安装依赖或改变环境的命令。需要这些操作才能验证时，记录未验证项并交由独立的已授权任务执行。
- 无法获取事实时明确缺失及其对判断的影响，不编造测试通过或以自动降级流程补齐证据。
