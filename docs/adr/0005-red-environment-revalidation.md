# ADR 0005：执行环境变化后的 Red 重验

状态：已采纳（2026-09-17，用户要求修复）

## 背景

实现开始后 Node、PATH 或测试工具安装变化可能使 Red 的命令摘要失效。旧证据不含分项摘要，无法证明是哪一项变化。直接改摘要会承认未经执行的 Red；在当前实现上重跑又可能已经全绿。

## 决定

新证据增加可选分项摘要，保持旧证据可读取，诊断仅显示变化类别。新增显式 revalidate-red 操作，绑定当前 Evidence ID，要求原始引擎 Claim 和 Red 工作区摘要匹配。在临时 Git 工作区重建历史字节并复制依赖，执行当前 Test Gate，复现原断言失败集合后才替换有效 Red。临时 runner 的路径和依赖图映射回原工作区计算命令身份，但执行前后仍检查真实隔离副本内容。

保持 Application Snapshot 不变。此操作不属于 ADR 0004 的配置迁移：测试资产及路径配置必须相同，仅重新执行既有合同。保留旧证据、恢复原因及原 Claim 基线，后续 acquire 和 modifiedFiles 校验仍以原实现起点为准。不重置重试预算，不允许活动租约或后续执行。操作在控制面事务内完成，失败不写入恢复状态，同请求幂等。

## 边界

仅从可验证的当前字节或 Git 基线重建；缺失历史内容时拒绝。依赖复制不使用指回原工作区的可写链接；macOS 临时目录先 canonicalize，再检查 pnpm/workspace 链接。外部依赖链接及源文件软链接暂不支持。文件隔离不是 OS 沙箱，测试仍需可信。真实任务应用恢复和 CLI 发布安装是独立操作。
