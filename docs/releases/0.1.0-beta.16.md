# 0.1.0-beta.16

本版简化 Agent 接入和日常工作流操作，作为 Beta 增量交付。真实 Host 体验验收尚未通过，不代表全部优化计划完成或生产可用性验收通过。

## 变更

- 新增 `agent status/setup`，显示磁盘安装状态与版本，支持安全、幂等安装和 dry-run；磁盘安装不代表当前 Host 已加载。
- Driver 升至 v15，补充 `complete` JSON 示例、相对草稿路径、业务 modifiedFiles 和逐步骤读取 Skill 的规则。
- 新增 `agent project setup/remove`，可恢复地维护 AGENTS.md 受管块，保留用户内容；当前原子文件更新仅支持 macOS。
- 按 feature、fix、assessment、docs 分流：修复使用专用诊断及 tasks，评估使用只读工作流。
- 新增 `continue/status/complete`，减少手工传递 Lease 和 ArtifactRef，保留原有授权、审批、重试和可信验证边界。
- 文件系统权限错误提供可操作的脱敏提示，覆盖真实 sandbox 下的 EPERM 等失败。

## 验证与已知限制

发布前本地完整测试记录为 1105/1105 通过；本次重新执行类型检查、构建与 Contract 测试（85/85）。npm 发布另由门禁强制要求发布提交的 main push CI 全部六项必需作业成功，并核对本地及远程标签。

真实 Codex Host 已实际执行咨询、评估、修复准备、功能澄清、文档修改及新会话恢复。仍存在高低层命令混用、产物章节/YAML 需要试错、默认 60 秒 Lease 不适合长时间 Agent 操作、子命令帮助缺失等问题；最终评估场景超时，不能判定真实体验验收通过。Issue/Wiki 外部交付尚未完成真实验收。详见 [验收记录](../acceptance/agent-usability.md)。

## 更新

```sh
npm install -g ws-spec-kit@0.1.0-beta.16 --registry=https://registry.npmjs.org
wspec --version
wspec agent status --client codex
wspec agent setup --client codex
```

旧版或自定义 Driver 不会被自动覆盖。先确认旧文件身份，将其移到目标目录外保留，再执行对应客户端的 setup。重新启动 Host 会话以加载新 Driver；status 仅验证磁盘状态。
