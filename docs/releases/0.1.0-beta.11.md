# 0.1.0-beta.11

本版改善执行环境变化和会话中断后的续作体验，保留测试证据、审批和外部写入校验。

- 新增 `recover <id> --actor <actor> --reason <原因>`，自动选择已有的 Red 路径恢复或隔离环境重验，避免手工传递 Evidence/Attempt ID。
- `inspect` 显示当前步骤、执行与中断预算、下一步建议；循环子步骤使用实际实例的预算。
- 租约中断退回本次预占的执行次数，单独记录中断；真实失败仍消耗执行预算。既有耗尽状态不自动清零。
- 新增 `revalidate-red`，在隔离目录重建原 Red 基线，以当前环境复现原断言失败后形成新证据，保留当前实现与历史审计。
- 新证据记录配置、Node、环境、reporter、runner 分项摘要，诊断不输出环境明文；旧证据保持可读取。
- 修复 macOS 临时目录路径别名造成的 pnpm 依赖链接误判。
- Driver 接入恢复建议，恢复成功后继续领取，需审批或无法自动恢复时停止。

## 更新

```sh
npm install -g ws-spec-kit@0.1.0-beta.11 --registry=https://registry.npmjs.org
wspec --version
```

已安装的旧 Driver 需按安装器支持的受管理文件更新流程更新并由 Host 重新加载，CLI 升级不会自动覆盖 Skill。

## 验证边界

本次验证覆盖本地自动化、打包安装及隔离 Red 重现。真实宿主及 Connector 平台验收仍以 `docs/acceptance/release-report.md` 为准。

本地验证记录：全量首轮执行 1,037 项（1,010 通过、27 失败）；失败集中在审查修正期间的 Driver 摘要和旧中断计数断言。最终 Driver 安装/真实 CLI 合同 55/55、最终正文与路由 20/20、受影响工作流与循环恢复用例 6/6 均重测通过。另有协议与循环建议检查 81/81、干净消费者安装 3/3 通过，lint/typecheck/build 通过。循环建议新文件不在首轮启动时的文件列表中，已纳入上述专项验证。
