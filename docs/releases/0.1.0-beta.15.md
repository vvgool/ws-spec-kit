# 0.1.0-beta.15

本版修复 CI 环境与受支持平台不一致的问题，并增加 npm 发布前的 CI 门禁。

- Driver 安装相关的 Contract、E2E 测试在 macOS runner 执行；通用 Unit、Integration 和构建检查继续在 Ubuntu 执行。
- 测试临时目录放到 runner 私有目录，使模拟 Provider CLI 满足生产执行器的路径权限校验；不放宽安全规则。
- Linux 测试用 Node 复制到私有目录，避免 runner 的可写工具缓存路径被安全执行器拒绝。
- 凭据持久化测试检查实际凭据 HOME/配置目录，避免把用户目录内合法的 Git 仓库身份路径误报为泄漏。
- Unicode 文件名测试显式创建调用者使用的拼写，兼容 Linux 区分 NFC/NFD、macOS 可能视其为同名的差异。
- `npm publish` 在构建前验证：工作区干净、位于 main、本地/远程版本标签及远程 main 指向当前提交，且该提交最新 main push CI 的全部必需作业成功。
- CI 失败、未完成、缺少作业，或引用其他提交的成功记录时，发布被拒绝。

## 更新

```sh
npm install -g ws-spec-kit@0.1.0-beta.15 --registry=https://registry.npmjs.org
wspec --version
```

本次未修改 Driver Skill，无需因本版重装。

## 发布与验证边界

先提交版本变更并推送 main，等待 CI 完成，再将 `v0.1.0-beta.15` 标签推送到同一提交，最后执行 `npm publish --tag beta --registry=https://registry.npmjs.org`。发布需要已登录的 GitHub CLI，并由 `prepublishOnly` 自动检查 CI 和重新构建。

CI 通过只代表仓库自动化验证通过。真实宿主及 Connector 平台验收仍以 `docs/acceptance/release-report.md` 为准。
