# 0.1.0-beta.17

本版修复实现期间调整测试辅助资产后，Work Item 无法查询或恢复的问题。

- 区分事件链损坏与测试证据过期；inspect/status 可返回明确恢复建议，真正断链仍被拒绝，不再被掩盖为内部错误。
- 原专项测试未改写、无活动租约且尚无后续证据时，recover 可在隔离的原产品基线上使用当前辅助测试资产重验。原失败断言必须仍失败，才会记录新 Red；保留旧证据、审计信息和产品改动基线，后续 Green Gate 不豁免。
- 支持复制链接到同仓库已登记 checkout 的 node_modules，在隔离目录重定位依赖链接；不共享可变依赖文件，其他外部依赖根仍拒绝。
- Vitest 的 runner 路径及依赖图按复制来源映射身份，避免隔离副本路径变化造成误报；真实依赖文件内容发生变化时仍拒绝。
- 普通 .DS_Store 不参与测试证据扫描，软链接仍被拒绝。
- 后续阶段的测试资产变化会明确阻塞，不再提示无法成功执行的 acquire。

## 验证

2048.IO 的现存 Work Item 已实际恢复为 implement ready，隔离基线产生原有的 8 个断言失败；游戏主目录及任务工作树内容摘要均保持不变。详见 [验收记录](../acceptance/test-evidence-recovery.md)。

发布由 prepublishOnly 强制校验当前提交的 main push CI 六项必需作业全部成功，以及本地标签、远程 main 和远程标签一致。此前完整测试首轮的文档表遗漏已修正，Contract 与恢复专项已复测。

本版未修改 Driver（仍为 v15）。beta.16 记录的命令混用、模板试错、60 秒 Lease 及 Issue/Wiki 外部验收等限制不因本次恢复修复而消失。

## 更新

```sh
npm install -g ws-spec-kit@0.1.0-beta.17 --registry=https://registry.npmjs.org
wspec --version
wspec inspect <workItemId>
```

若 inspect 返回 revalidate-red，按 nextAction.reason 执行一次 recover，并按新返回的状态继续；不要重新创建任务或手工改写历史证据。
